## 1. Как пользоваться этим файлом

1. **Запланированная работа идёт сюда** (будущее). **Сделанная — в [`FIXES.md`](FIXES.md)**
   с датой и записью «проблема → исправление → проверка» (конвенция §15.5 в PROJECT_HANDOFF).
2. Отмечать пункт (`[x]`) только когда он сделан **и проверен** (сегодня это тесты + три проверки
   `tsc`; после миграции — `cargo test` + `clippy`).
3. В отличие от датированных аудит-документов, **этот файл можно свободно переписывать** —
   он не «снимок» на дату.
4. Два жёстких инварианта проекта сохраняются при любом плане из этого файла:
   **рендерер ↔ main только через мост**, и **main → диск только валидированная атомарная запись**.

**Главный вывод (он и определяет весь план).** Рендерер — не узкое место: 439 КБ UI-кода и

## 3. Фаза 0 — сначала дешёвые победы, без переписывания (дни, а не месяцы)

Сделать **до** любой работы по переносу. Это дёшево, обратимо и либо снимает необходимость
переписывания, либо точно показывает, что ещё болит.

- [x] **Electron 32 → 44.x.** Двенадцать мажоров улучшений V8/Chromium. Приложение уже
      соответствует ужесточённым дефолтам (`contextIsolation`, `sandbox`, без `remote`),
      так что переход должен быть почти механическим.
- [x] **Собрать main-процесс в один файл** (esbuild или `electron-vite`) вместо 25 отдельных
      CJS-модулей, которые выдаёт `tsc` — меньше чтений диска и вызовов `require` при старте.
- [x] **Отгружать как `asar`**, `asarUnpack` — только для того, чему действительно нужны файлы.
- [x] **Ленивая инициализация сервисов в `main.ts`:** сначала окно, потом MCP-менеджер, кэш
      Obsidian, TTS и опрос системы.
- [x] **Перестать порождать `npx` для MCP-серверов.** Reference-сервер, поднятый через `npx`,
      стоит целого процесса Node (сотни МБ, секунды). Самая крупная реальная победа, и она же
      убирает проблему зомби-процессов на Windows, описанную в `FIXES.md`.
- [x] **Структурированный вывод решений агента** (GBNF-грамматика / `response_format`): текущая
      схема «ответь JSON-объектом» плюс цикл корректирующих повторов стоит *дополнительных полных
      проходов LLM*.
- [x] **Двухуровневая маршрутизация моделей:** маленькая модель решает, какой инструмент вызвать;
      большая пишет только финальный ответ. Решения об инструментах — самый частый вызов LLM в цикле.
- [x] **Токен-бюджет и суммаризация памяти** (сейчас история обрезается только по числу записей).
- [x] **`llama.cpp` / `llama-server` как полноценный провайдер** (кэш промпта, выгрузка на GPU).
- [x] **Локальный STT `whisper.cpp`** вместо опоры на Web Speech API — заодно разблокирует Фазу 3.
- [x] **CI (GitHub Actions):** `vitest` и три проверки `tsc` на каждый пуш.
- [x] **Иконка приложения** — генерируется `scripts/generate-icon.ps1` и встраивается через
      `afterPack`/rcedit (выполнено и проверено 23.09.2026).
- [ ] **Подпись кода** — установщик не подписан; нужен реальный сертификат (открытое решение §10).

**Критерии выхода из Фазы 0:** прогретый старт < 1.5 с (**достигнут**: 0.42–0.63 с), RAM в покое

## 4. Цель: ядро на Rust, сверху — тонкие фронты

### 4.1 К чему стремимся

| Метрика | Сейчас | Цель после миграции |
|---|---|---|
| Установщик | 110.9 МБ | **8–15 МБ** |
| Распакованное приложение | 381.2 МБ | **15–30 МБ** |
| RAM в покое | 352–355 МБ | **80–180 МБ** |
| Прогретый старт | 0.42–0.63 с | **0.4–1.0 с** |
| Холодный старт | 3.22 с | **1–3 с** |
| Запуск MCP-сервера | самодостаточный ESM-бандл через `ELECTRON_RUN_AS_NODE` (без `npx`) | внутри процесса или один маленький бинарь |
| Скорость отрисовки UI | Chromium 152 | **такая же** (WebView2 — тоже Chromium) |
| Латентность ответа LLM | зависит от модели | **не изменится — так и задумано** |

### 4.2 Почему Rust (и это не «просто быстрее»)

1. **Ни встроенного браузера, ни рантайма Node** — именно там 381 МБ и большая часть RAM.
2. **Настоящее ядро вместо «god hook»:** цикл агента, инструменты, MCP и безопасность становятся
   отдельной библиотекой, которую можно юнит-тестировать и переиспользовать в CLI или веб-фронте.
3. **Memory safety для приложения, которое выполняет shell-команды** на машине пользователя.
4. **Линейный по времени regex** (крейт `regex`) упрощает слой ReDoS-защиты, который сейчас живёт
   в `electron/lib/regex-security.ts`.
5. **Один бинарь — много фронтов:** десктоп (Tauri), CLI и позже веб-UI поверх одного ядра.

## 5. Целевая архитектура

```
┌──────────────────────────────┐        ┌───────────────────────────────────────────┐
│  kora-desktop (Tauri 2)      │        │  kora-core (Rust, без UI)                 │
│  WebView2 / WKWebView        │◄──────►│  цикл агента · реестр инструментов ·      │
│  React UI — без изменений    │ JSON-  │  безопасность · конфиг · аудит · MCP ·    │
│  window.kora.* сохранён как  │  RPC   │  шлюз к LLM                               │
│  тонкий адаптер над invoke() │ stdio  │                                           │
│                              │        │  он же: kora-cli (тот же бинарь, без UI)  │
└──────────────────────────────┘        └───────────────────────────────────────────┘
```

**Ключевой приём:** рендерер сначала остаётся **байт в байт неизменным**. Новая оболочка реализует
тот же объект `window.kora.*`, который сейчас отдаёт `electron/preload.ts`, но каждый метод просто
проксирует вызов в ядро. Тогда 7096 строк React, темы Tailwind, i18n, рендер markdown и граф
Obsidian во время переноса трогать не нужно — меняется только слой под ними.

**Предлагаемая раскладка крейтов**

```
crates/
  kora-core/        цикл агента, планировщик, guard'ы, память, промпты, реестр инструментов
  kora-security/    shell-фильтр, правила путей, regex-guard, SSRF-guard, движок политик
  kora-llm/         шлюз к провайдерам (OpenAI-совместимые, Anthropic, OpenRouter), SSE, ретраи
  kora-mcp/         MCP-клиент и менеджер (rmcp), конфиг, жизненный цикл
  kora-store/       конфиг, чаты, mcp.json, audit-лог (атомарная запись, keyring для секретов)
  kora-rpc/         типы и транспорт JSON-RPC 2.0 (сегодня stdio, позже localhost)
  kora-cli/         headless-фронт (агент без какого-либо UI)
  kora-desktop/     оболочка Tauri 2 (src-tauri) + собранный React
```

### 6.3 Инструменты: 28 встроенных

`shell, file, patch_file, grep, open, dir, write, rename, delete, mkdir, stat, exists, help, volume,
mute, brightness, windows, shutdown, restart, sleep, lock, search, clipboard, ai_chat, ai_list_models,
ai_test_connection, tts_synthesize, tts_voices` + динамические `mcp__<сервер>__<инструмент>`.

На Rust каждый становится реализацией трейта (`trait Tool { fn metadata(); async fn run(); }`) с той
же формой метаданных, чтобы `buildSystemPrompt()` работал без изменений. Подтверждение остаётся
полем первого класса в метаданных, а ошибки обработчика по-прежнему возвращаются как
`{ success: false, error }` — никаких паник и исключений внутрь цикла агента.

### 6.4 `!`-команды и цикл агента

- `src/lib/commands.ts` (29 команд, 9 опасных) → `kora-core::commands`. `!calc` оставить
  рукописным парсером — **никогда** не вводить сюда вычислитель выражений, умеющий исполнять код.
- `src/agent/*` (orchestrator 16 КБ, tool-registry 19 КБ, guards, planner, memory, prompts) →
  `kora-core`. Примитивы ретраев и guard'ов (`IterationBudget`, `ToolLoopGuard`,
  `detectDegenerateRepetition`, `boundToolError`, `parseLlmErrorReason`) переносятся **вместе со
  своими тестами**, а не пишутся с нуля.
- Межпроцессные контракты сохранить байт в байт: `[kora:<reason>]`, `[DONE]`, `[ERROR] `, `[ABORT]`
  и протокол решения «один JSON-объект».

### 6.5 Конфигурация, секреты, аудит

| Сегодня | После |
|---|---|
| `~/.kora/config.json`, атомарная запись tmp+rename, очередь записи | `kora-store` на `serde` + `tempfile` + `rename`, тот же формат файла (схему не ломать, данные пользователя не терять) |
| Ключи API, зашифрованные Electron `safeStorage`, `enc:<base64>` | системный keyring через крейт `keyring` (Windows Credential Manager / macOS Keychain / libsecret) |
| `~/.kora/chats.json`, `sanitizeChats()`, бэкап в `.corrupt-*` | то же поведение, тот же формат |
| `~/.kora/mcp.json` | тот же формат |
| `~/.kora/audit.log` (JSON lines, ротация 10 МБ) | тот же формат, аппендер на `tracing` |

**Требование к миграции (не пропускать):** у существующих пользователей ключи зашифрованы
`safeStorage`. Первый релиз на Rust обязан либо один раз прочитать legacy-значения `enc:` и
перезаписать их в системный keyring, либо сохранить документированный путь расшифровки на время
перехода. Молча потерять ключи API — единственный недопустимый исход всей переписки.

### 6.7 Рендерер: что остаётся, что меняется

разницы в скорости не будет на фоне любого пункта Фазы 0.

### 6.8 Тесты: 138 → Rust

Железное правило переносится без изменений: **тесты импортируют реальные продакшн-модули, а не
копию логики.** Цель: те же 138 сценариев как `cargo test` (юнит + parity), плюс новые тесты на то,
чего нет вообще — атомарные записи и восстановление после порчи файлов в `kora-store`, ретраи и
бэкофф в `kora-llm`, жизненный цикл `kora-mcp` и новая модель политик/capability.

### 6.9 Чек-лист паритета — что не должно сломаться

Перенос заменяет всё, что ниже UI, поэтому нужен явный чек-лист:

- [ ] у каждого из 59 каналов есть аналог на Rust и smoke-тест
- [ ] опасные инструменты по-прежнему требуют подтверждения; поток `!confirm` ведёт себя так же
- [ ] команды, найденные в **выводе модели**, по-прежнему никогда не выполняются
- [ ] маркеры `[kora:<reason>]` и терминаторы потока не изменились
- [ ] форматы файлов `~/.kora/*` не изменились; legacy-ключи `enc:` читаются один раз
- [ ] audit-лог не изменил форму
- [ ] i18n EN/RU полная; все 4 темы корректно выглядят в WebView2 (и в WKWebView)
- [ ] граф Obsidian остаётся работоспособным на 5000+ заметок

## 8. Реестр рисков

| Риск | Влияние | Что делаем |

| Кривая обучения Rust снижает темп фич | среднее | сначала переносить чистые модули (P2) — там и выигрыш, и тесты |
| Пробелы в плагинах Tauri (трей, автообновление, deep links) | низкое–среднее | проверять каждый плагин на P1/P2, а не на P4 |

| Расползание объёма — «раз уж переписываем, давайте и UI переделаем» | высокое | §9 «Вне области работ» обязателен к соблюдению |
| Холодный старт на машине без WebView2 Runtime | низкое (в Windows 11 есть) | bootstrapper Tauri; задокументировать |
